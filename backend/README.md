# Firewall Log Analyzer Backend

Node.js + TypeScript backend foundation for firewall log uploads, persisted metadata, and future analysis jobs.

## Install

```bash
cd backend
pnpm install
```

Copy the example environment file if you want local overrides:

```bash
cp .env.example .env
```

Start the local PostgreSQL database from the project root:

```bash
docker compose up -d postgres
```

Generate the Prisma client and apply migrations:

```bash
pnpm prisma:generate
pnpm prisma:migrate
```

## Run

```bash
pnpm dev
```

The server defaults to `http://localhost:4000`.

Build and run compiled output:

```bash
pnpm build
pnpm start
```

## Endpoints

### `GET /api/health`

Returns service health.

### `POST /api/uploads`

Accepts one firewall log file using `multipart/form-data`. The raw file is written to `UPLOAD_DIR` with a generated safe file name. Upload and job metadata are stored in PostgreSQL.

Allowed extensions:

- `csv`
- `tsv`
- `txt`
- `log`
- `json`
- `ndjson`

Example:

```bash
curl -F "file=@sample.csv" http://localhost:4000/api/uploads
```

Response:

```json
{
  "uploadId": "uuid",
  "jobId": "uuid",
  "fileName": "sample.csv",
  "status": "queued"
}
```

### `GET /api/uploads/:id`

Returns stored upload metadata only. Raw file contents are never returned.

### `GET /api/jobs/:jobId`

Returns persisted job status. Supported statuses are `queued`, `processing`, `completed`, and `failed`.

### `GET /api/uploads/:id/analysis`

Returns the latest stored deterministic analysis result for an upload, including summary, log profile, traffic intelligence, sensitive ports, policy review, findings, normalized logs, parse warnings, and row count.

### `GET /api/analysis-runs/:analysisRunId`

Returns a specific stored analysis run.

## Configuration

Environment variables:

- `ACTION_EXECUTION_MODE=direct_controlled` enables one-click Execute for validated catalog actions. `lab_fast` and `safe` remain available. Raw AI/CLI text is never sent to a connector in any mode.

Assessment endpoints:

- `POST /api/assessments/full-analysis`
- `GET /api/assessments/:id`
- `POST /api/assessments/:id/hardening-suggestions`
- `POST /api/recommendations/:id/create-action-plan`
- `GET /api/actions/catalog` and `GET /api/actions/catalog/:vendor`
- `POST /api/actions/match`

- `PORT`: server port, default `4000`
- `CORS_ORIGIN`: allowed frontend origin, default `http://localhost:5173`
- `DATABASE_URL`: PostgreSQL connection string
- `UPLOAD_DIR`: local directory for stored upload files, default `./storage/uploads`
- `MAX_UPLOAD_MB`: upload size limit, default `25`

## Security Notes

- File contents are written to disk but are never logged or returned as raw file content by API responses.
- Analysis is deterministic and runs in-process after upload; no external services are called.
- Uploads are limited by extension and size.
- Disk file names are generated by the server; original file names are kept only as metadata.
- SHA-256 checksums are calculated during upload.
- CORS is restricted to `CORS_ORIGIN`.
- Helmet security headers are enabled.
- Request body size is limited.
- Production error responses do not include stack traces.
- Upload and job metadata are persisted in PostgreSQL.
