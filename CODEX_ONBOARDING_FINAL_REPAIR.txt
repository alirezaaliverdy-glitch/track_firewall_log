Goal: make device registration reliable while preserving honest connector semantics.

Critical facts from the audit:
- The current onboarding commit requires connectorInvoked=true and therefore cannot register an offline/unreachable device.
- Onboarding sessions are stored only in an in-memory Map.
- The UI offers API for FortiGate/MikroTik although the registered onboarding connectors are SSH-only.
- Existing historical credential records may be undecryptable with the current CREDENTIAL_ENCRYPTION_KEY.
- createDevice/updateDevice sync Device+Asset transactionally, but onboarding performs a second sync; site/location and some audit work remain outside the same atomic boundary.
- The frontend onboarding status union omits backend statuses credential_missing, credential_invalid, and preview_failed.
- npm test does not include phase3-device-asset-convergence.test.ts or task20-diagnostics.test.ts.

PHASE 2 - Add honest unverified registration
Implement a separate path that registers a device without pretending that connection verification succeeded.

Backend contract:
POST /api/device-onboarding/sessions/:sessionId/register-unverified
Body may contain the current onboarding draft.

Required behavior:
- Reject plaintext secrets.
- Validate vendor, platform, device name, host, integer port 1-65535, and environment.
- Credential reference is optional for unverified registration.
- Detect an existing Device with the same normalized vendor + host + managementPort. Return a structured 409 with existing deviceId and route instead of creating duplicates.
- Atomically create/update Device, Asset projection, management IP, optional Site, optional Location, and AuditLog.
- Persist Device status=unknown.
- Persist capabilities.onboarding with verificationStatus="unverified", connectorInvoked=false, connectionVerified=false, platform, and createdAt.
- Return status=completed and result containing deviceId, assetId, route, verificationStatus="unverified", connectorInvoked=false, connectionVerified=false.
- Do not execute SSH/API or discovery in this endpoint.
