# Current handoff

Standalone VMware ESXi now has selectable SSH and SOAP API registration. The integration remains **partial** and host-only: pinned RSA-SHA2 SSH provides read-only host/hardware/storage/network inventory, while verified SOAP supports richer inventory and a bounded set of reviewed host actions. SSH and connectivity monitoring reuse the same shared authenticated session. No VM mutation or arbitrary SSH command execution is implemented. See [scope and acceptance notes](docs/ESXI_STANDALONE.md) and [Persian connection setup](docs/ESXI_CONNECTION_SETUP_FA.md).

Backend/frontend builds, 17 focused/regression tests and validation of 225 catalog items passed. A real loopback SSH server verified host-key rejection and session reuse; mocked-API Chromium tests verified SSH/API selection and separate fields at 1440/390px. The local API/web are deployed and healthy; no new migration was needed for SSH. A real ESXi host has not been available, so no live-host action has been tested. Before production deployment, ensure the earlier ESXi enum migration is applied with an enum-owning role, and validate the pinned RSA host key, least-privilege ESXCLI inventory, TLS and one approved non-disruptive API action on the actual ESXi version. SSH CPU/RAM utilization, hardware health and VM count remain unknown, not zero. Alternate ESXi channels are disabled until separately configured. Never claim all ESXi features or live compatibility as complete without that acceptance.

Project rules are in AGENTS.md; current work status is in docs/CURRENT_STATUS.md and docs/TASK_HISTORY.md.
