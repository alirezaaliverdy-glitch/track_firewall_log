# آپلود و بازگردانی بک‌آپ

مسیر: «بک‌آپ تجهیزات ← آپلود و بازگردانی». شرکت و دستگاه را انتخاب کنید، فایل را آپلود کنید یا یکی از بک‌آپ‌های برنامه را انتخاب کنید، سپس «بررسی و پیش‌نمایش» را بزنید. پیش‌نمایش هیچ تنظیمی را تغییر نمی‌دهد. اجرای بازگردانی فقط برای مدیر است؛ فایل به همان دستگاه ثبت‌شده متصل می‌شود، نه دستگاه دلخواه یا IP واردشده در فایل.

## روش هر وندور

| وندور | روش و پیش‌نیاز | محدودیت مهم |
| --- | --- | --- |
| Cisco IOS / IOS-XE | فایل کامل running-config دارای version؛ انتقال SCP به فایل موقت Flash و configure replace با زمان تأیید سه‌دقیقه‌ای؛ خواندن و مقایسه سپس configure confirm | فقط پلتفرم دارای SCP و configure replace/timer؛ نسخه باید سازگار باشد. startup-config خودکار نوشته نمی‌شود. تأییدنشده نباید موفق نمایش داده شود. |
| MikroTik | export متنی rsc دارای نسخه؛ RouterOS 7.16+، SFTP، dry-run بومی سپس import و مقایسه خروجی تازه | import ادغام است، نه جایگزینی کامل. فرمان add تکراری ممکن است خطا دهد یا تغییر نیمه‌کاره ایجاد کند. بک‌آپ باینری و reset خودکار پشتیبانی نمی‌شود. dry-run صحت عملکرد شبکه را تضمین نمی‌کند. |
| FortiGate | فایل کامل و بدون ماسک conf؛ نسخه/مدل سازگار، admin-scp و حساب مجاز؛ SCP به fgt-restore-config | دستگاه ممکن است ری‌استارت شود. پایان انتقال موفقیت بازگردانی نیست؛ پس از برگشت اتصال «بررسی نتیجه» باید تنظیمات را دوباره بخواند و مقایسه کند. فعلاً دستگاه واقعی برای تست نداریم. |
| Linux | tar.gz از کل /etc؛ Python 3 و حساب root یا sudo -n مجاز برای گیرنده ثابت برنامه | تأیید جداگانه کل /etc لازم است. فایل‌های کاربران، رمز، SSH و شبکه ممکن است عوض شوند. سرویس‌ها خودکار ری‌استارت نمی‌شوند. فایل‌های اضافی موجود حذف نمی‌شوند: روش overlay است، نه بازسازی دیسک. |

برای Linux، فایل‌ها، پوشه‌ها و symlinkهای معتبر داخل /etc بررسی می‌شوند. symlink دنبال نمی‌شود؛ مسیر مقصد دارای پوشه symlink رد می‌شود. traversal، node ویژه، hardlink و قالب PAX/sparse پذیرفته نمی‌شوند. مجوز و مالک فایل‌ها حفظ می‌شوند؛ فراداده پوشه موجود تغییر نمی‌کند. هر فایل با جایگزینی اتمی نوشته و SHA-256/مالک/مجوز آن بررسی می‌شود؛ کل عملیات چندفایلی تراکنش اتمی نیست. قبل از بازگردانی کامل، دسترسی کنسول مستقل داشته باشید. بدون ری‌استارت، تأیید فایل‌ها به معنی تأیید فعال‌شدن تنظیمات سرویس نیست.

pfSense و Sophos فعلاً در بازگردانی پشتیبانی نمی‌شوند؛ قابلیت گرفتن بک‌آپ pfSense به معنی قابلیت بازگردانی آن نیست. فایل تنظیمات، بک‌آپ کامل سیستم، دیتابیس یا Firmware نیست.

## کنترل اجرا و نتیجه

- پیش‌نمایش ده دقیقه اعتبار دارد. تغییر مقصد، پورت، مسیر اتصال یا زمان آخرین تغییر اعتبارنامه آن را باطل می‌کند؛ تغییر نمونه CPU چنین اثری ندارد.
- تأیید به hash فایل متصل است. فقط درخواست intent=execute می‌تواند اجرا شود. Linux علاوه بر تأیید عمومی، تأیید مستقل RESTORE FULL ETC می‌خواهد.
- پیش از تغییر، بک‌آپ تازه ایمنی از دستگاه گرفته می‌شود. خرابی آن اجرای بازگردانی را متوقف می‌کند؛ فایل آن در تاریخچه قابل دریافت است.
- همان ActionPlan، PolicyGuard، کانکتور ثبت‌شده و audit استفاده می‌شوند؛ متن خام AI اجرا نمی‌شود. حداکثر چهار بازگردانی هم‌زمان و یک عملیات فعال برای هر دستگاه مجاز است؛ تأیید دوباره یک طرح اجرا را تکرار نمی‌کند.
- نتیجه‌های «فایل تأیید شد، فعال‌سازی دستی لازم است»، «منتظر بررسی»، «نیازمند بازبینی» و «موفق» جدا هستند. قطع اتصال یا خطای میانی، موفقیت نیست. پس از توقف API، طرح نیمه‌کاره خودکار تکرار نمی‌شود؛ مدیر باید دستگاه و بک‌آپ ایمنی را بررسی کند. طرح متوقف‌شده همچنان قفل آن دستگاه را نگه می‌دارد؛ رفع دستی پس از بررسی لازم است.
- تاریخچه شامل کاربر، دستگاه، زمان تهران، روش، نتیجه و بک‌آپ ایمنی است. حذف فایل آپلودی فقط برای مدیر و با تأیید مستقل است؛ دستگاه و تاریخچه را حذف نمی‌کند.

## ذخیره و تست

فایل‌ها در DeviceSnapshot موجود، با کلید رمزنگاری برنامه ذخیره می‌شوند؛ SHA-256 هنگام دریافت و اجرا بررسی می‌شود. هیچ محتوای فایل، رمز یا خروجی حساس در تاریخچه، audit یا خطا نمایش داده نمی‌شود. محدودیت فایل ۲۰ MiB است؛ Linux حداکثر ۱۲۸ MiB بازشده، ۱۰هزار ورودی، ۸ MiB هر فایل و ۶۴ MiB محتوا دارد. کلید رمزنگاری و دیتابیس باید مستقل و امن نگهداری شوند. دانلود فایل رمزنگاری‌شده نیست و ممکن است اطلاعات حساس داشته باشد.

تست‌های backup-restore.test.ts، linux-restore-receiver.test.ts و تست‌های قبلی بک‌آپ/حذف/مجوز مجموعاً ۳۹ مورد هستند. گیرنده Linux در کانتینر آزمایشی روی پوشه موقت تست شده، نه /etc سرور واقعی. smoke-backup-restore.mjs فقط آپلود آزمایشی، دانلود، پیش‌نمایش خواندنی Cisco و Linux موجود و رد intent نامعتبر را تست می‌کند و داده‌های آزمایشی خودش را پاک می‌کند؛ هیچ بازگردانی واقعی اجرا نمی‌کند. smoke-backup-ui.mjs واکنش‌گرایی، multipart، لغو پنجره و تأیید جداگانه Linux را بررسی می‌کند. کانکتورهای تغییر واقعی روی تجهیزات کاربران اجرا نشده‌اند؛ این تست‌ها جای تأیید بازگردانی در آزمایشگاه هر مدل/نسخه را نمی‌گیرند.

Compose محلی: docker-compose.firewall.yml. برای انتشار از docker-compose.production.yml با imageهای immutable و مقادیر امن واقعی محیط استفاده شود. هیچ مهاجرت دیتابیس یا حذف volume لازم نیست.
