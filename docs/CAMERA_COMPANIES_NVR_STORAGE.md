# شرکت‌ها، پایش NVR و مدیریت فضای گفتگو

## مسیر استفاده

از «دوربین‌ها» ابتدا شرکت را انتخاب کنید؛ هر شرکت فضای مشاهدهٔ خودش را دارد. مدیر می‌تواند همان‌جا شرکت بسازد. دستگاه‌های قدیمی در «بدون شرکت» محفوظ‌اند؛ از جزئیات دستگاه شرکت را تعیین کنید. نسبت‌دادن خودکار براساس IP انجام نمی‌شود. شرکت آرشیوشده از فهرست، رسانه، پایش و اجرای اقدام کنار گذاشته می‌شود. مالکیت فضای کاری همچنان روی همهٔ درخواست‌ها کنترل می‌شود.

در جزئیات NVR، «پایش الآن» را بزنید. پایش دوره‌ای اختیاری است (پیش‌فرض خاموش، فاصلهٔ ۱ تا ۶۰ دقیقه). هر نتیجه زمان بررسی دارد و فقط ۴۸ خلاصهٔ اخیر نگهداری می‌شود. دریافت تصویر مستقل است؛ انتخاب شرکت یا روشن‌کردن پایش، پخش تصویر را شروع نمی‌کند.

## دریافت واقعی اطلاعات هارد

در «هارد و ذخیره‌سازی ← تنظیم مسیر دریافت هارد» مسیر سازگار را انتخاب کنید:

| خانوادهٔ سازگار | مسیر خواندن | اطلاعات قابل دریافت |
| --- | --- | --- |
| Hikvision / HiLook / HiWatch | ISAPI روی پورت وب دستگاه | ظرفیت، آزاد/مصرف، وضعیت گزارش‌شده؛ دما و ارزیابی SMART فقط در پاسخ واقعی سرویس اختیاری |
| Dahua / Amcrest / برخی OEMهای سازگار | CGI روی پورت وب دستگاه | ظرفیت و مصرف پارتیشن‌ها، خطای گزارش‌شده؛ موفقیت API معادل سلامت فیزیکی نیست |
| Xiongmai / XMEye / Sofia و OEMهای سازگار | DVRIP روی TCP، معمولاً 34567 | ظرفیت، آزاد و مصرف از StorageInfo؛ واحد هگز/MiB تبدیل می‌شود؛ وضعیت خام پارتیشن بدون تفسیر حدسی نگهداری می‌شود |

گزینهٔ خودکار فقط بر اساس برند دریافت‌شده از ONVIF یک آداپتور را انتخاب می‌کند؛ برای برند ناشناس ورود حدسی یا امتحان‌کردن چند رمز انجام نمی‌شود. کاربر می‌تواند خانواده و پورت را صریحاً تعیین کند. IP و VPN همان دستگاه ثبت‌شده است. در صورت تفاوت حساب مدیریتی و ONVIF، حساب هارد جداگانه و رمزگذاری‌شده ذخیره می‌شود؛ پاسخ API هیچ نام کاربری/رمزی از تنظیمات هارد برنمی‌گرداند.

برای نمونهٔ پنل ارسال‌شده با مدل 8016F-4K و پورت TCP 34567، مسیر DVRIP نامزد مناسب است؛ تشخیص قطعی و دادهٔ هارد به ورود موفق بستگی دارد. دسترسی خواندنی HTTP به پنل از محیط توسعه تأیید شد؛ تست ورود با رمزِ تصویر در فرمان اجرایی توسط بررسی امنیتی محیط رد شد و دور زده نشد. دریافت هارد روی همان دستگاه هنوز تأیید نشده است؛ اطلاعات ورود باید از فرم امن برنامه وارد شود. هیچ تغییر تنظیم، فرمت، راه‌اندازی مجدد، شروع SMART یا ضبط روی دستگاه واقعی انجام نشد.

این پیاده‌سازی همهٔ مدل‌ها را تضمین نمی‌کند. ONVIF استاندارد مشترک تصویر/هویت و برخی سرویس‌های ضبط است؛ همهٔ ضبط‌کننده‌ها ظرفیت، SMART، CPU یا حافظه را از آن ارائه نمی‌کنند. دستگاه‌های دیگر به API/SDK/MIB رسمی همان مدل و آداپتور تست‌شده نیاز دارند. این نسخه دریافت SNMP هارد یا SDK باینری عمومی اضافه نمی‌کند. قابلیت ناموجود «سالم» نمایش داده نمی‌شود؛ وضعیت صفر پارتیشن DVRIP نیز به SMART موفق تعبیر نمی‌شود. پرشدن هارد در ضبط چرخشی الزاماً خرابی نیست.

## کنترل و ایمنی

پایش فقط خواندنی است. SOAP و درخواست HTTP فقط به IP خصوصی ثبت‌شده، با پاسخ محدود و مهلت قطعی می‌روند؛ تغییر مسیر HTTP دنبال نمی‌شود، XML دارای DTD/entity رد می‌شود و TLS اعتبارسنجی دارد. DVRIP فقط ورود، StorageInfo و خروج را پیاده می‌کند، با یک تلاش ورود، سقف فریم و مهلت محدود؛ هیچ رابط ارسال دستور دلخواهی ندارد. HTTP و DVRIP را فقط روی شبکهٔ مورد اعتماد یا VPN استفاده کنید؛ پورت مدیریت NVR را عمومی نکنید. در خطای رمز یا قفل حساب، پایش دوره‌ای خاموش می‌شود تا تلاش‌ها ادامه پیدا نکنند.

اقدامات موجود مانند راه‌اندازی مجددِ ONVIF همچنان از پیش‌نمایش، تأیید، PolicyGuard، کانکتور واقعی و ممیزی عبور می‌کنند؛ دریافت پاسخ پذیرش، اثبات پایان راه‌اندازی مجدد نیست. قالب‌های Linux/MikroTik و تنظیمات آزمایشگاهی تغییر نکرده‌اند. تغییر شرکت، مسیر یا تنظیم اتصال پیش‌نمایش قدیمی را نامعتبر می‌کند.

## فایل و نگهداری گفتگو

- سقف هر فایل: ۵۰ MiB؛ حداکثر سه فایل در هر پیام. پراکسی فقط برای مسیر پیوست تا ۱۶۰ MiB مجاز است، نه همهٔ آپلودها. مهلت تراکنش فایل بزرگ افزایش یافته و آزمون با محتوای واقعی ۵۰ MiB انجام می‌شود.
- سقف محتوای پیوست: ۵۱۲ MiB در فضای کاری، ۱۵۳۶ MiB کل برنامه، ۲۰۰ MiB برای هر کاربر در ۲۴ ساعت. حذف فایل، مصرف روزانهٔ ممیزی‌شده را صفر نمی‌کند. نوع/امضا/نام فایل، دسترسی، CSRF، نرخ و هم‌زمانی محدودند؛ فایل‌ها آنتی‌ویروس نشده‌اند.
- اپراتور صریحاً حذف برگشت‌ناپذیر را تأیید کرد: پیام و پیوست گفتگو پس از ۳۰ روز؛ پیام و پیوست تیکت بسته پس از ۹۰ روز؛ یا مازاد بر ۵۰۰۰ پیام **در هر گفتگوی مشمول**. تیکت باز، تسک، دادهٔ امنیتی و ممیزی حذف نمی‌شوند.
- اجرا ساعتی و دسته‌بندی‌شده است: حداکثر ۵۰ گفتگو و ۵۰۰ پیام از ابتدای هر گفتگو در هر نوبت. زمان‌ها و تعداد از «فضای فایل‌ها و نگهداری پیام‌ها» برای مدیر قابل تغییر/غیرفعال‌سازی است؛ مشاهده‌گر فقط می‌بیند. حذف خودکار را با آگاهی از سیاست نگهداری فعال نگه دارید؛ بازیابی فقط از بکاپ مستقل ممکن است.
- حذف، پیوست را با FK پاک و ارجاع پاسخ/منبع تسک را خالی می‌کند؛ خود تسک و ممیزی باقی می‌مانند. کلاینت پیام‌های حذف‌شده با پاکسازی را هم کنار می‌گذارد. پاکسازی ترتیب صندوق گفتگو را تغییر نمی‌دهد.
- محتوا در PostgreSQL bytea است. حذف منطقی ردیف به معنی کوچک‌شدن فوری فایل دیتابیس روی دیسک نیست؛ PostgreSQL فضای قابل استفادهٔ مجدد دارد. WAL، بکاپ، رشد تیکت‌های باز و کل دیسک باید جداگانه پایش شوند. تضمین پرنشدن همیشگی دیسک ادعا نمی‌شود.

## مهاجرت و انتشار

دو مهاجرت افزایشی `20261018150000_community_storage_retention` و `20261018160000_camera_company_monitoring` لازم‌اند. مهاجرت هیچ دستگاهی را حدسی به شرکت نمی‌چسباند. مالک قدیمی جدول Company ممکن است با نقش مهاجرت API متفاوت باشد؛ مالک جدول/مدیر دیتابیس باید فقط REFERENCES(id) را با `scripts/deploy/prepare-camera-migration.sql` و نقش API صحیح اعطا کند. پیش‌بررسی انتشار، مالکیت جدول‌های قابل تغییر و این مجوز محدود را کنترل می‌کند؛ نقش API به superuser تبدیل نمی‌شود. آزمون مهاجرت با نقش غیرمالک AppUser/Company نیز وجود دارد.

تغییرات این نوبت محلی‌اند؛ پوش/انتشار سرور بدون درخواست صریح انجام نمی‌شود.
