# Vendor Monitoring Workspace

## هدف

صفحه `/monitoring` یک داشبورد کوتاه برای انتخاب وندور و دستگاه، اجرای بررسی و دیدن چهار شاخص ضروری است. نمودار چهاررنگ همین شاخص‌ها را خلاصه می‌کند و جزئیات تخصصی Linux همچنان در مسیر `/monitoring/linux/:deviceId` باقی می‌ماند تا صفحه اصلی شلوغ نشود.

## اصل صحت داده

- تعریف پروفایل یا عبارت «آماده بررسی» نتیجه سلامت نیست.
- وضعیت هر حوزه فقط وقتی از `parsedResult.sections` نمایش داده می‌شود که ActionPlan واقعی `connectorInvoked=true` داشته باشد.
- پیش‌نویس، انتظار تأیید، خطای پیش از Connector و نبود داده به‌ترتیب همان وضعیت واقعی را نشان می‌دهند و به «سالم» تبدیل نمی‌شوند.
- برای وندور بدون Connector، چک‌لیست فقط راهنمای دستی است و دکمه اجرای خودکار ندارد.
- صفحه هیچ امتیاز انطباق، گواهی امنیتی یا پوشش ساختگی تولید نمی‌کند.

## جریان داده

1. `GET /api/daily-check/profiles` پروفایل‌ها، مرجع استاندارد و راهنمای وندورها را برمی‌گرداند.
2. `GET /api/daily-check/devices/:deviceId/profile` فقط اطلاعات غیرمحرمانه آمادگی، وضعیت اتصال، وجود Credential و زمان آخرین تست را برمی‌گرداند.
3. `GET /api/action-center?deviceId=...` آخرین ActionPlan چک روزانه و شواهد فراخوانی Connector را فراهم می‌کند.
4. ساخت برنامه از Command Catalog انجام می‌شود و همان مسیر محافظت‌شده `Preview -> Confirm -> PolicyGuard -> Connector -> Audit/Result` را حفظ می‌کند.

## چهار شاخص اصلی رابط کاربری

پروفایل فنی هر وندور همچنان دست‌کم هفت حوزه دقیق برای جمع‌آوری و تحلیل دارد، اما صفحه اصلی آن‌ها را فقط در چهار گروه قابل‌فهم خلاصه می‌کند: سلامت دستگاه، کارایی، شبکه و امنیت. برای هر وندور محتوای گروه‌ها متناسب است؛ برای نمونه Linux «سرویس و شبکه»، MikroTik «فایروال و VPN» و FortiGate «Policy، VPN و HA» را برجسته می‌کند. این خلاصه‌سازی فقط نمایشی است و شواهد Connector یا جزئیات نتیجه را تغییر نمی‌دهد.

رنگ‌های پیش‌فرض نمودار فقط هویت چهار گروه هستند و با شفافیت کمتر نمایش داده می‌شوند. رنگ سلامت واقعی تنها پس از اجرای Connector به سبز، زرد یا قرمز تبدیل می‌شود و مرکز نمودار در نبود نتیجه عبارت «بدون داده» را نشان می‌دهد.

## پایش تخصصی Linux

مسیر `/monitoring/linux` نمای ناوگان را بدون جدول عریض نمایش می‌دهد. هر کارت فقط هویت سرور، وضعیت، امتیاز سلامت، CPU، RAM، Disk و زمان آخرین جمع‌آوری را نشان می‌دهد و موارد نیازمند توجه را بالاتر می‌آورد. جست‌وجو، فیلتر وضعیت، جمع‌آوری تک‌دستگاه و جمع‌آوری همه دستگاه‌ها روی همان نمای ناوگان در دسترس است.

مسیر `/monitoring/linux/:deviceId` جزئیات همان دستگاه را در بالای ناوگان باز می‌کند: Snapshot سلامت، شاخص‌های عملیاتی، هشدارهای ثبت‌شده و روند CPU/RAM/Disk در ۲۴ ساعت گذشته. نمودار روند فقط از `MetricSample`های ذخیره‌شده و وضعیت کارت‌ها فقط از `HealthSnapshot` واقعی استفاده می‌کند؛ نبود داده صریحاً نمایش داده می‌شود و به مقدار سالم تبدیل نمی‌شود.

## سطح پشتیبانی

| وندور | وضعیت | مسیر |
| --- | --- | --- |
| Linux | Connector واقعی | `linux.daily-check` / `linux-ssh` |
| MikroTik | Connector واقعی | `mikrotik.daily-check` / `mikrotik-ssh` |
| FortiGate | Connector واقعی | `fortigate.daily-check` / `fortigate-ssh` |
| Cisco | راهنمای دستی | بدون ادعای اجرای خودکار |
| pfSense | راهنمای دستی | بدون ادعای اجرای خودکار |

## مبنای استاندارد

- [NIST SP 800-137 — Information Security Continuous Monitoring](https://csrc.nist.gov/pubs/sp/800/137/final)
- [NIST Cybersecurity Framework 2.0](https://www.nist.gov/cyberframework)
- [CIS Critical Security Controls v8](https://www.cisecurity.org/controls/v8)
- راهنمای رسمی عملیات و پایش هر وندور، از جمله RouterOS Logging و FortiGate Monitors

این مراجع برای ساخت چک‌لیست عملیاتی استفاده می‌شوند؛ نمایش آن‌ها به معنی ارزیابی یا گواهی انطباق نیست.
