# نمودارهای فشردهٔ تجهیزات

داشبورد برای هر دارایی چهار نمودار کوچک دارد: CPU، حافظه، دریافت/ارسال ترافیک و دسترسی دستگاه. رنگ‌ها ملایم‌اند؛ انیمیشن فقط تغییر دادهٔ واقعی را نمایش می‌دهد. حرکت با دکمهٔ داخل بخش قابل خاموش‌کردن است و تنظیم کاهش حرکت سیستم هم رعایت می‌شود. نمودار تک‌نمونه یک نقطه دارد؛ دادهٔ ساختگی برای پرکردن نمودار تولید نمی‌شود.

نمایش هر ۱۰ ثانیه بازخوانی می‌شود. جمع‌آوری منابع با حداقل فاصلهٔ دو دقیقه و حداکثر دو تجهیز هم‌زمان انجام می‌شود؛ این پایش دوره‌ای است، نه تضمین دریافت لحظه‌ای بدون تأخیر. دادهٔ منابع بیش از پنج دقیقه «تاریخی» محسوب می‌شود. روند منابع از حداکثر ۲۰۴۸ نمونهٔ دو ساعت اخیر و روند دسترسی از آخرین ۱۲۰ بررسی ساخته می‌شود. تغییر وضعیت دسترسی مستقل از امکان ورود و خواندن سنسورهاست.

ترافیک مربوط به اینترفیس نام‌برده‌شده است، نه مجموع تمام پورت‌ها (جمع پورت‌های bridge/VLAN می‌تواند دوباره‌شماری کند). دو نمونهٔ معتبر از شمارندهٔ بایت برای محاسبهٔ Mbps لازم است؛ reset شمارنده یا بازهٔ نامعتبر نرخ منفی تولید نمی‌کند. Cisco نرخ میانگین پنج‌دقیقه‌ای خود تجهیز را گزارش می‌دهد و این روش زیر نمودار مشخص است. MikroTik دادهٔ RAM/دیسک را از مقدار واقعی کل/آزاد می‌سازد؛ SSH نام‌های نقل‌قول‌دار و شمارنده‌های چندخطی و جداشده با فاصله را پشتیبانی می‌کند. REST فقط خواص نام و بایت دریافت/ارسال را صریح می‌خواند.

مقدار ناموجود صفر نیست. اگر ورود رد شود، کارت راهنمای اصلاح اعتبارنامه دارد. در بررسی واقعی این مرحله ESXi با SSH_AUTH_FAILED ورود را رد کرد؛ برای تکمیل CPU/RAM/ترافیک آن، از تنظیم اتصال دارایی اعتبارنامهٔ معتبر و دارای مجوز خواندن را انتخاب کنید. اثر انگشت هاست و بررسی امنیتی حذف نشده‌اند؛ حساب یا تنظیمات هاست به‌صورت خودکار تغییر نکرده است.

سایدبار دسکتاپ sticky و به‌اندازهٔ viewport است؛ منوی طولانی اسکرول داخلی مستقل دارد. علت ازکارافتادن آن overflow:hidden روی والد کل برنامه بود که با overflow:clip رفع شد؛ منوی کشویی موبایل حفظ شده است.

منابع طراحی/جمع‌آوری: [MDN position](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/position)، [کاهش حرکت](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion)، [RouterOS interface counters](https://help.mikrotik.com/docs/spaces/ROS/pages/139526175/Interface%2Bstats%2Band%2Bmonitor-traffic)، [REST property lists](https://help.mikrotik.com/docs/spaces/ROS/pages/47579162/REST%2BAPI).

نتیجهٔ آزمون این تغییر: ۱۶ تست سنسور/دادهٔ نمودار/ESXi موفق؛ آزمون Chromium واقعی با API نمونه‌سازی‌شده برای چهار وندور، sticky sidebar، اندازه‌های ۱۴۴۰/۳۹۰/۳۲۰، حالت کاهش حرکت و نبود درخواست تغییردهنده موفق. بررسی واقعیِ خواندنی روی Linux/Cisco روندها را تأیید کرد؛ MikroTik دوازده اینترفیس معتبر و سپس دو نمونهٔ نرخ RX/TX ثبت کرد. ساخت‌های تولید API و وب موفق و سرویس‌ها سالم بودند. موفقیت جمع‌آوری احراز هویت‌شده، شاهد آنلاین‌بودن سنسور اتصال هم می‌شود؛ ردشدن ورود صرفاً خطای پایش است و به‌اشتباه آفلاین فرض نمی‌شود. FortiGate/Sophos دستگاه ثبت‌شده برای تست زنده نداشتند.
