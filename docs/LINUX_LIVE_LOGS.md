# پایش زندهٔ لاگ لینوکس با یک جمله

در داشبورد، بخش «اقدام با یک جمله»، تجهیز لینوکسی دارای SSH و اعتبارنامهٔ ذخیره‌شده را انتخاب کنید. مثال‌ها:

- «لاگ nginx» — ابتدا فایل استاندارد وب؛ اگر موجود نبود، تشخیص فقط‌خواندنی یک کانتینر واقعاً سازگار.
- «لاگ سرویس docker» یا «لاگ سرویس my-api» — journal واحد systemd؛ با نام دقیق واحد.
- «لاگ کانتینر my-api» — stdout/stderr همان کانتینر در حال اجرا؛ نه اجرای فرمان داخل کانتینر.
- «لاگ IP 192.0.2.10» — جست‌وجوی دقیق IP در journal سیستم؛ برای لاگ وب، نام منبع را هم بگویید.
- «لاگ nginx برای IP 192.0.2.10» — فیلتر IP در منبع وب انتخابی.
- «لاگ سرویس my-api شامل «connection refused»» — عبارت literal، نه regex یا فرمان پوسته.
- «لاگ خطاهای سرویس my-api»، «لاگ کرنل» یا «لاگ /var/log/secure».

پیش‌نمایش، منبع، فیلتر، تجهیز و کلید SSH را نشان می‌دهد. اولین کلید را با تجهیز تطبیق دهید. دکمهٔ «تأیید و شروع پایش» یک تأیید است؛ قبل از آن هیچ فرمان لاگ روی تجهیز اجرا نمی‌شود (فقط بررسی کلید میزبان پیش از احراز هویت). درخواست مبهم روشن‌سازی می‌خواهد؛ دستورات خام کاربر/AI اجرا نمی‌شوند.

## مسیر اجرا و دسترسی

`intent -> linux.live-logs -> ActionPlan -> preview -> one confirmation -> PolicyGuard -> linux_live_log_query -> Linux SSH connector -> verified source/live session -> audit -> cursor long-poll UI`

- تمرکز فعلی Linux با SSH اصلی است. اپراتور و مدیرِ دارای دسترسی اقدامات می‌توانند پایش خودشان را آغاز کنند؛ مشاهده‌گر یا حساب فاقد بخش، نه. جلسه به کاربر و مالک فضای کاری متصل است؛ شناسهٔ تصادفی به‌تنهایی اجازهٔ خواندن نمی‌دهد.
- ثبت قالب/پلنر/کانکتور واقعی، `intent=execute`، اعتبار پارامترها و ممیزی لازم‌اند. تنظیمات quick-controlled/lab و رفتار سایر دستورات دست‌نخورده‌اند. `linux_read_auth_logs` قدیمی به این جریان جدید هدایت نمی‌شود؛ شناسهٔ صریح کاتالوگ لازم است. مهاجرت دیتابیس لازم نیست.
- کلید SSH در پیش‌نمایش و اتصال واقعی یکسان است؛ کلید تأییدشده ذخیره می‌شود. تغییر کلید، تنظیم اتصال، اعتبارنامه، شرکت، مالکیت یا مسیر VPN دسترسی را متوقف می‌کند. مسیر VPN اعتبارسنجی می‌شود؛ این قابلیت تونل جدید فعال نمی‌کند.
- بعد از long-poll، اعتبار نشست ورود، نقش، مجوزها و تجهیز دوباره بررسی می‌شوند؛ لغو دسترسی نباید متنِ منتظر تحویل را آزاد کند.
- منابع journal، فایل‌های مشخص auth/secure/syslog/messages/kernel/UFW/nginx/Apache/fail2ban و Docker پشتیبانی می‌شوند. خواندن فایل دلخواه، credential file، shell، exec داخل کانتینر، regex دلخواه یا تغییر سرویس مجاز نیست. فایل باید regular/readable و مسیر canonical آن همان مسیر مجاز باشد.
- تشخیص وب فقط با شواهد واقعی Docker و یک نتیجهٔ سازگار انجام می‌شود. تنها ID/Image/Ports درخواست می‌شود، نه env/labels/inspect کامل. پاسخ ناقص، بیش از ۱۰۰ کانتینر، چند تطابق یا نبود منبع باعث خطای روشن می‌شود؛ کانتینر حدس زده نمی‌شود. حالت «سرویس nginx» صریحاً journal را می‌خواند و با «لاگ nginx» وب متفاوت است.

## نمایش و محدودیت‌ها

- ۵۰ خط اخیر منبع، سپس جریان پیوستهٔ SSH. تحویل HTTP با cursor/long-poll بیدارشونده با رویداد است؛ timeout خالی ۱۰ ثانیه و تجمیع کوتاه ۲۰۰ms، نه جمع‌آوری batch ده‌ثانیه‌ای. تأخیر شبکه/نوشتن لاگ منبع جداست؛ SLA سخت realtime وعده داده نمی‌شود.
- ۵۰۰ رویداد یا ۱MiB برای هر جلسه، حداکثر ۸ جلسهٔ فعال کل و ۲ برای هر کاربر؛ جلسه‌های بسته محدود/منقضی می‌شوند. تا ۳۰ دقیقه؛ ترک صفحه/قطع خواندن پس از حدود ۴۵–۵۰ ثانیه جریان را می‌بندد. پنجرهٔ قدیمی آرشیو نیست و از دست‌رفتن دادهٔ پنجره اعلام می‌شود.
- سقف خط/نرخ ورودی و زمان فرمان/اتصال از حافظه و اتصال رهاشده جلوگیری می‌کند. قطع منبع، نبود ابزار، فایل/واحد/کانتینر ناموجود و نداشتن مجوز جداگانه گزارش می‌شوند. خط بسیار بزرگ یا جریان افراطی ممکن است نیاز به منبع محدودتر داشته باشد.
- متن خام لاگ روی دیسک یا در ActionPlan/audit ذخیره نمی‌شود؛ audit شناسه‌ها، وضعیت و شمارنده‌ها را نگه می‌دارد. فرم پرس‌وجو و نتیجهٔ شروع نشست همچنان در سابقهٔ اقدام وجود دارند؛ رمز/توکن را در عبارت درخواست وارد نکنید.
- رمز/توکن/cookie/authorization/URL credential و بلوک کلید خصوصی متداول پیش از تحویل پوشانده/حذف می‌شوند؛ redaction تضمین کشف همهٔ اسرار آزاد در متن نیست. نمایش React text است، نه HTML؛ کنترل‌های ترمینال و جهت مخرب حذف می‌شوند.
- جست‌وجوی داخل پنجره، مکث/ادامهٔ نمایش، توقف واقعی پایش، شمارنده‌های ورودی/مطابق، زمان تجهیز یا زمان دریافت با برچسب، هشدار پوشش و طراحی RTL روشن/تیره برای موبایل/دسکتاپ وجود دارد. مکث نمایش دریافت را قطع نمی‌کند.
- نبود رویداد، سلامت یا نبود حمله را ثابت نمی‌کند. فقط چیزی دیده می‌شود که سرویس واقعاً لاگ می‌کند و حساب SSH اجازهٔ خواندنش را دارد. حساب محدود پوشش کامل سیستم ندارد؛ sudo فقط بدون رمز امتحان می‌شود و سطح دسترسی تجهیز تغییر نمی‌کند. خطاهای فایل/Docker از الگوی متن تشخیص داده می‌شوند؛ اولویت journal دقیقاً از دستگاه است.
- جلسه‌ها در حافظهٔ یک API هستند؛ restart/deploy جلسه را می‌بندد. برای چند replica به sticky routing یا broker جلسه نیاز است؛ قابلیت فعلی آن را ادعا نمی‌کند.

## اعتبارسنجی

- `backend/test/linux-live-log-query.test.mjs`: intent فارسی/انگلیسی، ابهام، shell/path/option injection، IP دقیق IPv4/IPv6، متن literal، شدت، redaction و تشخیص کانتینر یکتا/کامل.
- `backend/test/linux-live-log-api.integration.test.mjs`: PostgreSQL ایزوله + SSH واقعی آزمایشی + HTTP واقعی؛ مسیر کامل کاتالوگ/preview/یک تأیید/PolicyGuard/کانکتور، تحویل رویداد مرتبط، scope، CSRF، سقف حافظه، توقف، منبع غیرقابل‌خواندن، کلید متفاوت، لغو مجوز حین long-poll و fallback واقعی فایل به کانتینر.
- `scripts/qa/capture-linux-live-logs.mjs`: فقط دادهٔ مصنوعی با APIهای intercept‌شده؛ هر دو تم در ۱۴۴۰/۳۹۰/۳۲۰px، preview بدون اجرا، یک تأیید، live/search/pause/resume/stop و HTML بی‌اثر.
- پذیرش مجاز ۲۰۲۶-۱۰-۲۱ روی یک دارایی لینوکسی ثبت‌شده: درخواست HTTP عادی با شناسهٔ موقت، پاسخ ۲۰۰ و دریافت لاگ همان درخواست از API واقعی در حدود ۵۲۲ms. بدون نگهداری متن/تصویر مشتری؛ نشست ورود موقت حذف و پایش متوقف شد. این تأیید یک دارایی/منبع است، نه همهٔ توزیع‌ها و پیکربندی‌ها.

قفل advisory اجرای اقدام در محیط تست نیز اکنون همان `TEST_DATABASE_URL` اعتبارسنجی‌شدهٔ Prisma را استفاده می‌کند؛ production همچنان `DATABASE_URL` قبلی را دارد. این اصلاح مانع تماس تست کامل با دیتابیس واقعی می‌شود.

مراجع رفتار منابع: [systemd journalctl](https://www.freedesktop.org/software/systemd/man/255/journalctl.html) و [Docker container logs](https://docs.docker.com/reference/cli/docker/container/logs/).
