روش صحیح شروع کار

  1. شرکت را بسازیدنام روشن و کد کوتاه یکتا انتخاب کنید.
  2. شرکت فعال را انتخاب کنیدپیش از ثبت دستگاه، زمینه سازمانی را بررسی کنید.
  3. دارایی‌ها را ثبت کنیدهر تجهیز باید به شرکت درست متصل باشد.
  4. دسترسی را محدود کنیدکمترین سطح دسترسی لازم را اختصاص دهید.

رفتار حذف و بازیابی

Soft Delete

حذف عادی شرکت ابتدا آرشیوی است تا پشتیبانی امکان بازیابی داشته باشد.

حذف دائمی

حذف آبشاری می‌تواند شرکت و دارایی‌های وابسته را پاک کند؛ فقط مدیر و با تأیید نام شرکت.

تمام درخواست‌ها باید با نشست معتبر، CSRF و مجوز مرکزی انجام شوند.

قبل از هر عملیات اجرایی

بالای صفحه نام شرکت و دستگاه انتخاب‌شده را کنترل کنید. این ساده‌ترین راه جلوگیری از تغییر روی تجهیز اشتباه است.

مهاجمان، Brute Force و یافته‌ها

رویداد خام به‌تنهایی هشدار نیست. موتور تشخیص رخدادها را بر اساس Vendor، سرویس، IP منبع، تعداد تلاش و بازه زمانی هم‌بسته می‌کند.

نشانه‌های Brute Force

  • تلاش‌های ناموفق تکراری از یک IP
  • SSH، WinBox، GUI، API یا VPN authentication failure
  • عبور از آستانه در بازه زمانی Rule
  • هم‌بستگی بین Vendor و سرویس هدف

قبل از مقابله بررسی کنید

  • IP عمومی یا داخلی و مالک آن
  • False Positive مانند Scanner مجاز
  • دستگاه‌ها و سرویس‌های هدف
  • اثر Block روی مدیریت یا کاربران واقعی
۱. مهاجم را باز کنید

شدت، تعداد رخداد، اولین و آخرین مشاهده و سرویس‌های هدف را ببینید.

۲. شواهد را اعتبارسنجی کنید

پیام‌های خام محدودشده، Finding مرتبط و دستگاه هدف را تطبیق دهید.

۳. پاسخ مناسب بسازید

Block موقت IP یا سخت‌سازی را به شکل ActionPlan بسازید؛ فرمان خام اجرا نکنید.

۴. نتیجه را دنبال کنید

Audit، نتیجه Connector و کاهش رخدادها را بعد از اقدام کنترل کنید.

IP مدیریتی خودتان را مسدود نکنید

PolicyGuard دوباره بررسی می‌شود، اما اپراتور همچنان باید Trusted Source، مسیر مدیریت و امکان Rollback را کنترل کند.

https://github.com/alirezaaliverdy-glitch/track_firewall_log.git track

# backend/.env و secretهای امن را قرار دهید
docker compose -f docker-compose.firewall.yml up -d --build
docker compose -f docker-compose.firewall.yml ps
