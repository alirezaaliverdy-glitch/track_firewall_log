# معماری نسخه Android

## تصمیم معماری

نسخه اول Android با **Capacitor 8 + رابط React موجود** ساخته می‌شود. بازنویسی کامل با Kotlin در این مرحله هزینه و ریسک دو کدبیس مستقل را ایجاد می‌کند، در حالی که محصول فعلی رابط واکنش‌گرا، RTL، مسیرهای عملیاتی و لایه‌های بومی SQLite، Secure Storage و SSH دارد.

معماری اجرایی:

```text
Android WebView (React UI)
  -> Native connection bootstrap
  -> Bearer session in Android secure storage
  -> HTTPS API / Fastify
  -> PostgreSQL + workers + connectors
```

- Backend منبع واحد حقیقت برای کاربر، دستگاه، Finding، ActionPlan، Audit و صف ایمیل است.
- رابط از جریان یک‌طرفه داده استفاده می‌کند: UI رویداد را می‌فرستد، API وضعیت را تغییر می‌دهد و UI وضعیت تازه را دوباره می‌خواند.
- رمز کاربر ذخیره نمی‌شود. فقط توکن تصادفی نشست در Secure Storage اندروید قرار می‌گیرد و همان نشست از صفحه مدیریت مدیر قابل ابطال است.
- ورود وب همچنان Cookie + CSRF است. ورود Android از Bearer استفاده می‌کند تا محدودیت Cookie میان WebView و سرور شبکه باعث خروج تصادفی نشود.
- آدرس سرور داده محرمانه نیست و در تنظیم محلی برنامه نگهداری می‌شود؛ توکن و credential هرگز در `localStorage` قرار نمی‌گیرند.

## شبکه و امنیت

- Release فقط HTTPS و گواهی مورد اعتماد سیستم را می‌پذیرد.
- HTTP شبکه محلی فقط در build نوع Debug فعال می‌شود و Manifest مجزای Debug دارد.
- درخواست‌های تغییردهنده Android بعد از اعتبارسنجی Bearer وارد همان Permission/PolicyGuard موجود می‌شوند؛ Bearer جای مجوز را نمی‌گیرد.
- هیچ API key، رمز، keystore یا آدرس خصوصی در APK کامپایل نمی‌شود.
- تغییر سرور، نشست امن قبلی را پاک می‌کند تا توکن یک سرور برای سرور دیگر ارسال نشود.

## رفتار آفلاین نسخه 1.0.1

این نسخه «server-connected» است. قطع اینترنت یا LAN باعث نمایش وضعیت آفلاین می‌شود و عملیات کنترلی بدون پاسخ واقعی سرور موفق اعلام نمی‌شود. Worker، تشخیص و صف ایمیل روی Backend مستقل از بازبودن اپ ادامه دارند. اجرای ActionPlan آفلاین و همگام‌سازی تعارض‌دار عمداً در نسخه اول فعال نیست.

## مسیر توسعه

1. نسخه 1.0: اتصال سرور، ورود امن، UI کامل و build اندروید.
2. نسخه 1.1: اعلان Push با شناسه دستگاه و تنظیم سطح هشدار.
3. نسخه 1.2: cache خواندنی رمزنگاری‌شده برای داشبورد و Findingهای اخیر.
4. نسخه 2: ارزیابی Kotlin/Compose فقط برای صفحه‌هایی که واقعاً به عملکرد یا API بومی بیشتر نیاز دارند.

## مبنای استاندارد

تقسیم UI/Data، منبع واحد حقیقت و جریان یک‌طرفه داده مطابق راهنمای معماری Android است. سیاست آفلاین نیز fail-closed نگه داشته شده تا عملیات امنیتی بدون اتصال واقعی صف یا اجرا نشوند. Build نوع Debug و Release از تنظیمات شبکه جدا استفاده می‌کنند.
